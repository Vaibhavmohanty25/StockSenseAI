# Phase 1 implementation plan

Goal: implement the user's Phase 1 specification within the existing README architecture.
Architecture: Django apps own persistence and application services; framework-independent
provider contracts live in src/data_ingestion. HTTP and Celery share application services.
Stack: Python 3.13, Django 5.2, DRF, PostgreSQL, Redis, Celery, Docker, pytest.
Spec: the Phase 1 requirements supplied in this conversation; README.md is unchanged.

## Decisions

- Use the explicitly requested backend/apps layout and /api/v1 routes.
- Require exchange when a symbol exists on multiple exchanges (HTTP 400 otherwise).
- Only NSE and BSE mock securities are supported, explicitly labeled synthetic.
- Validate a full bounded request before writing prices. A failed batch rolls back all
  prices but preserves its failed IngestionRun. Duplicate identical dates collapse;
  conflicting duplicate dates reject the batch. Unchanged rows are not counted as updates.
- Serialize writes per Security using PostgreSQL row locks, then bulk create/update.
- Bound historical requests to ten years and API responses to 1,000 prices.
- PostgreSQL is used for tests as well as development; no SQLite fallback.
- Future modules contain .gitkeep only. No future functionality or dependencies.
